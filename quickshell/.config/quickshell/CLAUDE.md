# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A [Quickshell](https://quickshell.org) desktop shell config written in QML, implementing a status bar for a Hyprland (Wayland compositor) session. This directory (`quickshell/.config/quickshell`) is one leaf of a larger personal dotfiles monorepo rooted at `/home/stick/Dotfiles` (other siblings: `hypr/`, `waybar/`, `alacritty/`, `nvim/`, etc.) — changes here don't affect those other configs.

Two shell "parts" exist so far: `bar/` (the status bar) and `powermenu/` (a full-screen logout/restart/shutdown overlay), and the layout is deliberately set up to hold more (a notification popup, an OSD, etc.) without their widgets colliding — see Architecture below.

## Running / testing changes

- Launch the shell: `qs -c quickshell` (or `quickshell -c quickshell`), pointing at this config directory. Quickshell hot-reloads QML on file save when already running, so for most edits just save and observe the running bar.
- There is no build step, linter, or test suite in this directory — it's plain QML/JS evaluated at runtime by the Quickshell engine. Validate changes by running the shell and watching the Quickshell log output for QML errors (bad bindings, missing imports, etc.).
- `.qmlls.ini` configures the QML language server (import paths, build dir under `/run/user/1000/quickshell/vfs/...`) — useful context if diagnosing editor/LSP issues, not something to hand-edit for app behavior.

## Architecture

- `shell.qml` — entry point. A `Scope` that instantiates every part (`Bar {}`, `PowerMenu {}`), made visible via `import "bar"` / `import "powermenu"`.
- Top-level layout: `config.js` and `components/` are **shared** across the whole shell; each shell "part" gets its own `modules/` subdirectory so widgets don't collide as more parts get added:
  ```
  shell.qml
  config.js
  components/        # shared: styling primitives + data singletons, used by any part
  bar/
    Bar.qml
    modules/         # bar-only widgets, not visible to other parts
  powermenu/
    PowerMenu.qml
    modules/         # powermenu-only widgets (currently just PowerButton.qml)
  ```
  A future part would follow the same shape: `notifications/Notifications.qml` + `notifications/modules/`, still importing the shared `../components` and `../config.js`. Each part's root file imports `"../components"` + `"../config.js"` (one level up) and `"modules"` (same directory); files inside a part's `modules/*.qml` import `"../../components"` + `"../../config.js"` (two levels up, back to the shared root). `shell.qml` instantiates every part as a sibling inside its `Scope`: `Bar {}` and `PowerMenu {}`.
- `Bar.qml` — the actual bar. Uses `Variants { model: Quickshell.screens }` to spawn one `PanelWindow` per monitor, anchored top/left/right. Each panel is a plain `Item` holding three independently-anchored `RowLayout`s (left / center / right) — **not** a single flat `RowLayout` with spacing hacks, since that previously caused stale sections to leave behind blank space when a widget collapsed to zero width. Each zone sizes to exactly its own content and gets `height: parent.height` explicitly (required since anchoring, unlike nesting inside a parent `Layout`, doesn't hand a height down to `Layout.fillHeight` children).
- `config.js` — plain JS module (imported as `Config`), **not** a QML singleton. Central source of truth for styling:
  - `Config.colors.*` — Catppuccin Mocha palette. Each bar module gets its own accent color (peach=CPU/GPU/MEM, mauve=clock, green=network, yellow=media, sky=volume, blue=mic) so new modules should pick an unused color rather than reusing one.
  - `Config.font.fontFamily` / `Config.font.sizes.*` — named size tiers (`xs`/`sm`/`base`/`md`/`label`/`heading`/`tooltip`/`title`) rather than ad-hoc `fontSize ± N` arithmetic; add a new tier here instead of hardcoding a pixel size in a widget.
  - `Config.bar.*` — `height`, `itemSpacing`, `moduleBorderWidth`, `popupPadding`. `Config.animation.*` — `fast`/`normal` durations for `Behavior on color`.
  - When something is genuinely reused for the same reason across modules (a border width, a popup's inner padding), it belongs here. One-off tuned values specific to a single widget's look (e.g. the calendar popup's circle sizes) don't need to be centralized — see the git history around the "general config" refactor for the reasoning.
- `components/` — shared, non-bar-specific pieces (usable by any future part):
  - `StyledText.qml` — a `Text` pre-wired with the config font; prefer this over bare `Text`.
  - `CalendarUtils.js` — `.pragma library` module of pure date-math functions (`weekDates`, `monthGrid`, `weekLabel`, `isSameDay`) used by the clock's week/year popups. No QML state, safe to share.
  - Data singletons (`pragma Singleton`), each wrapping a native or Quickshell-service data source and exposing plain reactive properties — consumed directly by module widgets, no manual polling glue needed in the UI layer:
    - `Time.qml` — computes the clock natively from `new Date()` on a 1s `Timer`. Does **not** shell out to `date` — that was the original scaffold behavior, replaced during the performance pass since forking a process every second is pure waste for something this cheap to compute in JS.
    - `SystemMonitor.qml` — CPU/mem/load/temp read natively from `/proc` and `/sys` via `FileView` (no subprocess); GPU stats via a periodic `nvidia-smi` call, since there's no sysfs equivalent for NVIDIA. Polls every 5s.
    - `NetworkMonitor.qml` — active interface/gateway/wifi-vs-ethernet all parsed natively from `/proc/net/route`, `/proc/net/wireless`, `/sys/class/net/*`; only the IP address needs a subprocess (`ip addr show`), and that only re-runs when the interface actually changes (an `ifaceChanged` flag inside `poll()`), not on every 5s tick — the IP practically never changes between polls.
    - `MediaPlayer.qml` — wraps `Quickshell.Services.Mpris` (fully reactive over D-Bus, no polling). Filters out `playerctld` from the player list since it's a shadow/mirror service that duplicates whatever's actually playing under its own MPRIS name.
    - `AudioMonitor.qml` — wraps `Quickshell.Services.Pipewire`. Sink (output) and source (mic) state live side by side in the same singleton since they're both "audio state"; nodes must be added to a `PwObjectTracker` or their properties won't stay live.
- `bar/modules/` — bar-only widgets, typically integrating with `Quickshell.Hyprland` or the `components/` singletons above.
  - `HyprlandWindows.qml` — per-screen workspace indicator. Splits workspaces across monitors by convention (screen 0 → workspaces 1-5, other screens → 6-10), renders occupied/focused workspaces as kanji numerals (see `kanjiMap`), and dispatches workspace-focus commands through `Hyprland.dispatch(...)`.
  - `Tray.qml` / `TrayContextMenu.qml` — the system tray. `Tray.qml` is `visible: trayRepeater.count > 0`, so it takes zero layout space (no width, no spacing gap) when there are no tray icons — `QtQuick.Layouts` fully excludes invisible children from both sizing and spacing, confirmed empirically. `TrayContextMenu.qml` is the extracted per-icon popup menu (`open()`/`close()`, `HyprlandFocusGrab` to dismiss on outside click).
  - `SystemTray.qml` — an earlier system tray implementation, **not imported anywhere**. Dead code, superseded by `Tray.qml`/`TrayContextMenu.qml`; don't assume it's live.
  - Widget + popup pairs follow one convention throughout: `XWidget.qml` is the bordered bar-label box; `XPopup.qml`/`XTooltip.qml` is a separate `PopupWindow` component the widget wraps in a `Loader` (see Performance below) instantiated with `anchor.item: root`. Plain info tooltips (`SystemMonitorTooltip`, `NetworkTooltip`) just toggle `visible` on hover. Popups with clickable content (`MediaPopup`, `AudioDevicesPopup`, `MicDevicesPopup`, the clock's week/year popups) need to survive the pointer moving off the widget and onto the popup itself — the pattern is a `closeTimer` (`Timer`, ~250ms) started on the widget's `onExited`, cancelled by a `HoverHandler` inside the popup's own `onHoveredChanged` (`hoverEntered`/`hoverExited` signals bridge the two).
  - Popup anchoring: `anchor.edges` is the point on the widget the popup attaches to, `anchor.gravity` is the direction it grows from that point (see `qs::core::PopupAnchor` semantics). `BottomEdge` alone (no `Left`/`RightEdge`) on both centers the popup under the widget — used for anything not flush against a screen edge. `BottomEdge | RightEdge` / `BottomEdge | LeftEdge` (anchor at the widget's own right corner, grow left) is for widgets flush against the *right* screen edge (`TrayContextMenu`), so the popup stays on-screen instead of overflowing past it.
  - `ArchLogoWidget.qml` does double duty: it's the leftmost bar item *and* the power-menu trigger (`onClicked: PowerMenuState.toggle()`). Styled as a "cutout" rather than the usual bordered box — a solid `Config.colors.sapphire` fill with the Arch glyph rendered in `Config.colors.mantle` (the bar's own background) so the logo reads as negative space, not colored text on a dark box like every other module.
- `powermenu/` — the logout/restart/shutdown overlay, a second full shell "part" alongside `bar/`.
  - `components/PowerMenuState.qml` — the shared singleton (`open` bool, `toggle()`/`close()`) both `bar/modules/ArchLogoWidget.qml` and `powermenu/PowerMenu.qml` reference; this is how two independent parts coordinate without either importing the other's `modules/`.
  - `PowerMenu.qml` uses a **different** lazy-load shape than the bar's popups, deliberately: the whole `Variants { model: Quickshell.screens }` block sits inside `Loader { active: PowerMenuState.open }` — bound directly to `open`, not a one-way "loaded once, then kept alive" flag. That means it's fully destroyed (not just hidden) on every close and rebuilt from scratch on every open, unlike the bar's hover popups which load once and reuse. This is intentional: a full-screen overlay is heavier per-instance (one `PanelWindow` + full scene graph per monitor) and, unlike a hover tooltip you might reopen every few seconds, is opened rarely enough that the rebuild cost on each open is irrelevant — so it's better to guarantee zero footprint while closed than to optimize for repeat-open speed. Because the `Loader` is now the sole existence gate, the `PanelWindow`'s `visible` and the inner `MouseArea`'s `focus` are just `true` (not `PowerMenuState.open`) — the item literally doesn't exist unless `open` is true, so there's nothing left for those bindings to conditionally guard. Each screen's `PanelWindow` is anchored to all four edges (full screen), `WlrLayershell.layer: WlrLayer.Overlay` so it sits above the bar and every other window, `WlrLayershell.keyboardFocus: WlrKeyboardFocus.Exclusive` + `focusable: true` to actually grab keyboard input for Escape-to-close. Background is `"#4D" + Config.colors.crust.substring(1)` — prepending a `4D` (30%) alpha byte onto the existing crust hex rather than hardcoding a separate translucent color.
  - **`Keys.onEscapePressed` must go on an `Item`, not the `PanelWindow` itself** — `Keys` is an `Item`-attached property, and `PanelWindow` isn't an `Item` (attaching it there fails silently with a `WARN: Could not attach Keys property` log, not a hard error). It's attached to the full-screen `MouseArea` instead (which *is* an `Item`).
  - Click-outside-to-close relies on plain QtQuick MouseArea event containment, no manual "consume" hack needed: the full-screen `MouseArea` (`onClicked: PowerMenuState.close()`) has the `RowLayout` of `PowerButton`s nested *inside* it. Since each `PowerButton` has its own `MouseArea`, and child items receive input before their ancestors, clicking a button is handled entirely by that button's own handler and never reaches the background's `onClicked` — no separate "swallow this click" logic required.
  - `PowerButton.qml` (`powermenu/modules/`) — reusable button: `icon`/`label`/`accentColor` required properties, `triggered` signal. `180×180`, square corners (`radius: 0`), filled with `Config.colors.mantle` by default (not transparent) and `Config.colors.surface0` on hover — deliberately *not* transparent-by-default like the bar's module boxes, since these need to read clearly as large tappable targets on a nearly-full-screen dim background. Uses `Config.font.sizes.display` (40px) for the icon — a size tier added specifically for this, since nothing else in the bar needs text that large.
  - Actions: Logout uses `Hyprland.dispatch("exit")` (native, matches the dispatch pattern already used in `HyprlandWindows.qml` for workspace switching); Restart/Shutdown use `Process` (`systemctl reboot` / `systemctl poweroff`) since there's no Hyprland-native equivalent for those.

## Conventions

- Styling always flows through `config.js`'s `Config.colors` / `Config.font.sizes` / `Config.bar` / `Config.animation` — add new tokens there rather than inlining values, but only when a value is genuinely reused for the same reason elsewhere; don't centralize one-off widget-specific tuning.
- Files using `required property` on delegates/components typically start with `pragma ComponentBehavior: Bound` (see `HyprlandWindows.qml`, `Tray.qml`) — keep that pragma when adding similar strict-bound components.
- Hover/active state transitions use `Behavior on color { ColorAnimation { duration: Config.animation.fast/normal } }` — follow this pattern for new interactive widgets rather than snapping colors instantly.
- Nerd Font icon glyphs live in the Supplementary Private Use Area (5-hex-digit codepoints, e.g. `U+F0200`) — hand-typing them is error-prone (easy to end up with a truncated 3-byte sequence plus a stray literal digit). Verify a codepoint actually exists in the installed font before using it:
  ```python
  from fontTools.ttLib import TTFont
  f = TTFont('/usr/share/fonts/TTF/JetBrainsMonoNerdFont-Regular.ttf', lazy=True)
  print(0xF0200 in f.getBestCmap())
  ```
  and prefer writing the character into the file programmatically (`content.replace("TOKEN", chr(0xF0200))`) rather than retyping it by hand. When patching multiple tokens this way in one pass, sort by descending token length first — a shorter token (e.g. `"SELECTED_ICON"`) can be a substring of a longer one (`"UNSELECTED_ICON"`) and get replaced first, corrupting it.
- After any change, validate with `timeout 4 quickshell 2>&1 | tail -60` from this directory — a clean run prints `Configuration Loaded` with no errors and exits on its own after the timeout. This is more reliable than watching the long-running instance, since its stdout/stderr is attached to a terminal pty that usually isn't reachable from the session making the change.

## Performance

This config went through a dedicated performance pass. The philosophy and the concrete decisions it left behind, so they don't get accidentally undone or re-litigated from scratch:

- **No polling where a signal exists.** `MediaPlayer.qml` (MPRIS) and `AudioMonitor.qml` (PipeWire) are fully event-driven over D-Bus — zero `Timer`s for their state. Only reach for a poll `Timer` when the data source genuinely has no push mechanism (procfs/sysfs, `nvidia-smi`).
- **No subprocess for something JS can compute.** `Time.qml` used to shell out to `date` every second; now it's `new Date()` + formatting. Before adding a `Process`, check whether the value can be derived from a file already-native to `FileView` or from JS itself — a spawn is orders of magnitude more expensive than either.
- **Don't poll something that rarely changes at the same cadence as something that does.** `NetworkMonitor`'s `ip addr show` call is gated on the interface identity actually changing, not run on every 5s tick like the throughput sampling next to it — same idea applies to any future subprocess-backed field that's mostly static.
- **Poll intervals are 5s** (`SystemMonitor`, `NetworkMonitor`) — was 2s originally, doubled for a real CPU reduction after confirming the data doesn't need to feel more live than that. `Time.qml` stays at 1s deliberately; a seconds-resolution clock that only ticks every 5s just looks broken, so don't "fix" that one for consistency.
- **`blockAllReads: true` on the `FileView`s in `SystemMonitor`/`NetworkMonitor` is intentional, not an oversight.** Quickshell's own docs say "we cannot think of a valid use case" for it and warn blocking reads freeze the UI thread — that warning is written for real files on real storage. These are `/proc`/`/sys` entries with no disk I/O, so the block is sub-microsecond, and the alternative (`blockLoading`) returns *stale* data after `reload()` instead of fresh, which breaks the poll-then-read-fresh pattern these singletons depend on. Don't "fix" this without re-reading `fileview.hpp`'s docs on the exact `blockLoading` vs `blockAllReads` semantics first.
- **Popups are lazy-loaded, then idle-unloaded.** Every widget's popup is wrapped in a `Loader` gated by a `*Loaded`/`menuLoaded` bool that starts `false` and flips true on first hover/click — before that, the popup doesn't exist (confirmed via `proxywindow.cpp`: Quickshell eagerly constructs a `QQuickWindow` C++ object for every declared `PopupWindow` regardless of visibility, as part of its hot-reload architecture, so a plain `visible: false` popup declared directly in QML is *not* free — wrapping it in a `Loader` is what actually defers that cost). Once loaded, a popup stays loaded and just toggles `visible` on subsequent opens — don't destroy/recreate on every hover, that trades a one-time cost for repeated GC/rebind churn. Each widget also has an `unloadTimer` (`Config.bar.popupIdleUnload`, currently 15 minutes) that's `restart()`ed on every use and, on firing, flips the `*Loaded` flag back to `false` — but only if the popup is currently `!visible`, so it never yanks a popup out from under an active hover. `ClockWidget` has two independent loaders/timers (week popup, year popup) since they load independently; `Tray.qml`'s `TrayContextMenu` gets one instance per tray icon delegate, each with its own timer.
- **Measuring memory/CPU on the long-running dev instance is unreliable.** A process that's hot-reloaded through dozens of edits in one session has fragmented allocator memory that doesn't reflect a clean run. For an honest RSS/CPU reading, start a genuinely fresh instance instead: `quickshell > /tmp/qs-test.log 2>&1 & sleep 6; ps -o pid,rss,%cpu -p $!`, then kill it — don't trust `ps` on the session's own long-lived instance for before/after comparisons.
- **This machine runs 2 monitors** (`hyprctl monitors -j` to check), so `Variants { model: Quickshell.screens }` in `Bar.qml` spawns a full second `PanelWindow` with its own complete widget tree — every `Loader`, `MouseArea`, and `Timer` in `bar/modules/` exists once per screen. The `components/` data singletons are still process-wide singletons (not duplicated), so this doesn't double any polling/D-Bus work, only the UI-side object count. This is inherent to mirroring the bar on both screens, not a bug to fix.
- **Considered and left alone:** `Text.renderType: Text.NativeRendering` on `StyledText` (lighter glyph rasterization for flat non-animated text, but a general Qt tuning knob rather than something Quickshell's docs endorse, and untested here) — worth trying if squeezing further ever becomes a priority again, but wasn't applied since it wasn't asked for and has minor caveats around opacity/transform blending (irrelevant to current usage, but worth knowing before adding animated opacity to any `StyledText` later).
